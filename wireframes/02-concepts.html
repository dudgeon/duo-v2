Organizing idea

Your job is to clear what needs you. Everything else (projects, tasks, files) is context that appears when you open a session. Borrowed directly from how Claude Code's Agent View and Projects overview group work.

Left

The fleet board, sorted by state then by wait time. Cards show the exact pending question, and some can be answered from the card. Filter chips scope by topic or project.

Middle

One session at a time, no tabs. A header pins it to its project and task. Quick-reply buttons and "next needing you" keep you in the queue.

Right

Context follows the session: a one-line project header, the document it's editing with a Changes view, and related tasks/sessions in that project so you can resume instead of starting fresh.

Daily loop

  1. Open Duo. The inbox says what's blocked on you.
  2. ⌥↓ through Needs-you, reply from the card or the console.
  3. Review Done, mark reviewed.
  4. "New work…" when you have a new ask: pick project → task → resume or new.

How it nudges habits

  • Idle sessions are a visible, resumable lane, so resuming is the default.
  • "New work…" always asks which project and task before starting a session.
  • Related-sessions panel surfaces the one you should resume.

Risks

  • Projects are second-class. Browsing a project's tasks takes an extra step (Projects ▾).
  • Home is just another project here; no special dispatch surface.
  • No tabs means switching between two sessions is a click in the inbox, not a tab.

B · Rooms organized by project

The app is a set of project rooms, one per folder, which is exactly Claude Code's model. The left pane is the project list; the selected project expands to its tasks and sessions. The console's tabs belong to that project only, with a thin cross-project attention strip above them. The right pane is the project's card (goal, health, key files) over the document.

Organizing idea

One room = one folder = one Claude Code project. You're always "in" a project, so it's never ambiguous where a session lives or where files go. Attention across projects is a strip, not the main surface.

Left

Projects grouped by topic with attention badges. Only the selected project expands, showing tasks with their session chips and any unlinked sessions. Starred Home sits on top.

Middle

Terminal tabs scoped to the selected project. The orange strip above lists sessions in other projects that need you; ⌥↓ jumps there and switches rooms.

Right

The rich project card: goal, health, next milestone, resume/new, and PROJECT.md. Below it, the document being edited, with PROJECT.md and Files as tabs.

Daily loop

  1. Open Duo in the room you left off in.
  2. The strip says if another room needs you; ⌥↓ visits it and comes back.
  3. In a room, pick a task → resume its session or start one.
  4. New ask → "New project folder…" or "＋ Task" in the right room.

How it nudges habits

  • You can't start a session without being in a room, so sessions always land in a project folder.
  • "Unlinked sessions" are shown inside the room with a "link" action.
  • "New project folder" is the primary button at the bottom of the project list.

Risks

  • Weakest at 6+ sessions across many rooms: the strip is one line.
  • The left pane holds two levels (projects and the expanded project); at 20 projects it's long.
  • Home is just the first room; its dispatch role isn't visible.

C · Chief of Staff organized by the Home agent

The app is a conversation with your director agent. Home triages what comes in, proposes where it goes, dispatches sessions in other projects and reports back. The left pane is Home's desk: triage inbox, dispatched work, and what needs you. The console has Home pinned as the first tab; worker sessions open beside it. The right pane shows whatever Home is talking about.

Organizing idea

You delegate organizing to Home. It's a normal Claude Code project (~/work/home, not a repo) with app-provided tools to create tasks and start or resume sessions elsewhere. Close to Claude Code's cloud "Projects" coordinator, but local and file-based.

Left

Home's desk: a triage inbox with explicit verbs (Accept / Pick other / Snooze / Decline) and a suggested destination with a reason; work Home dispatched; sessions needing you. Projects are collapsed below.

Middle

Home is the pinned first tab. Worker sessions open as tabs, marked "via Home" when Home started them. A footer states what Home is allowed to do and that every action is logged.

Right

Context follows the conversation: the project Home is discussing, the task it proposes (as a draft task file you can edit before saving), and the project's tasks and document.

Daily loop

  1. Say "morning". Home summarizes, routes the obvious, asks about the rest.
  2. Accept or redirect triage items from the cards.
  3. Jump to sessions needing you; come back to Home.
  4. "Tell Home…" for anything new; it picks the project and resumes or starts.

How it nudges habits

  • Home prefers resuming an existing session and says so ("resumed Results readout").
  • Every ask gets a project before it gets a session.
  • Routing decisions are logged in a readable file, so the organizing is auditable.

Risks

  • Strongly opinionated; if you don't want a director, the left pane is mostly empty.
  • Needs Home to have real tools (task creation, cross-project session control) and clear limits.
  • Browsing projects directly is a secondary path.

The console is scoped to the selected task: its sessions are the tabs. The right pane shows the task's project, its task file, and its deliverable.

What we heard

Requirements

Non-goals

Organizing idea

Tasks are the unit of work; sessions are attached to them. Attention rolls up from sessions to tasks, so "needs you" means a task is blocked on you. Tasks are markdown files with frontmatter inside the project (status, waiting_on, done_when, linked sessions).

Left

Tasks across all projects, grouped: Needs you, In progress, Ready for review, Ready to start (unblocked, no session yet), Waiting on others, Done. Project shown as a subtitle; filter chips scope it.

Middle

The selected task's header (done condition, Mark done) and its sessions as tabs. "＋" offers resume first, then new. A footer shows sibling tasks in the same project.

Right

The task's project as a header strip, its task file (frontmatter) and its deliverable document, with Files as a tab.

Daily loop

  1. Open Duo. Tasks needing you are on top.
  2. Work a task: answer its session, or resume/start one.
  3. Pick from "Ready to start" when you have capacity.
  4. Mark done; the deliverable is already in the project.

How it nudges habits

  • A session is always created from a task, so it lands in that task's project folder.
  • Resume is the first option on the ＋ tab because a task's prior sessions are right there.
  • "Ready to start" makes unblocked work visible without starting sessions prematurely.

Risks

  • Quick, taskless sessions ("quick q about tax rules") need a home: an "Unfiled" lane or auto-created task.
  • Project-level view (goal, health, all tasks) is one click away in the right strip, not primary.
  • Task state must be derived carefully: session phase ≠ task status.
