Round 1: App shell

Four ways to arrange the main window. They're deliberately rough: the question is what's the primary surface and how you get to work (projects, tasks, sessions, the home agent). One color only: orange = needs you. Sessions are marked ● needs input · ◐ running · ■ done/unreviewed · ○ idle.

keys 1–4

Strengths

  • Everything is visible at once. Easy to learn for anyone who has used VS Code or Finder.
  • The sidebar shows the actual folder structure, so the app and the filesystem never disagree.
  • "Needs you" sits right above the tree.

Weaknesses

  • The tree gets deep and noisy once you have 15+ projects.
  • Terminal tabs can come from different projects, so context gets muddy.
  • With 6+ sessions running, attention is just a short list, not a real view.

How it nudges habits

  • Projects are always visible. "＋" creates a real folder.
  • "Resume latest" is the main action, and "New session" is the secondary one.
  • "Unfiled folders" shows sessions started outside a project, so you can file them.

Strengths

  • Built for 6+ sessions: you see at a glance what's blocked on you.
  • "⌥↓ next needing you" lets you work through the queue like an inbox.
  • "Idle · resumable" is a column of its own, so resuming feels like the normal thing to do.

Weaknesses

  • The project and task structure is hidden behind the ▤ icon, and tasks become chips on cards.
  • Starting from a session encourages creating more sessions, not working inside a project.
  • Feels like a dashboard rather than a terminal.

How it nudges habits

  • "＋ New work…" asks: which project? which task? new or resume? (a flow to wireframe later).
  • Once 3+ sessions are idle in one project, the column could suggest closing some.

Why rooms

  • One room = one Claude Code project = one folder. It matches Claude Code exactly, so it's always obvious which folder a session lives in.
  • Tasks are listed first and sessions hang off them. Unlinked sessions are shown, but separately.
  • The ⌘O picker puts "New project folder" next to existing projects, so you can find an existing one or make a new one in the same place.

Strengths

  • Most closely matches Claude Code's model.
  • Shows tasks and sessions many-to-many directly: a task can have several session chips, and a session can appear under several tasks.
  • Each room has room for a goal, a status, and later a file tree.

Weaknesses

  • The overview of sessions needing you is only badges on tabs, so it's weak at 6+ sessions unless we add a global queue.
  • Topics barely appear (breadcrumb and picker only). That's fine if we keep topics light.

Variants to consider

  • C + B: make the Home room be the fleet board.
  • Use a left rail for rooms instead of top tabs, so 10+ projects fit.

D · Director Console home-agent-first

The Home agent is always docked on the left as your chief of staff. It triages, dispatches and reports. On the right are a queue of sessions across all projects and whichever session you're focused on. You can reach projects by asking Home, or through the rail.

Strengths

  • Treats the home-agent pattern you described as the main way of working.
  • Organizing is done for you: Home creates tasks, picks projects, and resumes sessions instead of starting new ones.
  • The queue tags work "dispatched by Home", which makes delegation visible.

Weaknesses

  • Opinionated. Users who don't want a director get a wasted pane (it could collapse).
  • Needs Home to be able to create tasks and start or resume sessions in other folders, through a CLI or MCP tools the app provides.
  • Two terminals side by side are dense.

Open question

  • Is Home a normal project (just starred, with a CLAUDE.md that tells it about the other projects) or a special kind of project with app-provided tools? A or C could also host it as a starred project.

React to these

  1. Which primary surface feels right: tree (A), board (B), rooms (C) or director (D)? Mixing them is fine, e.g. "C, but Home is B".
  2. Should the attention queue be global (always visible) or shown when you ask for it?
  3. Should terminal tabs stay inside one project (C) or mix projects (A/B/D)?
  4. Is the Home agent a starred normal project or a distinct mode?
