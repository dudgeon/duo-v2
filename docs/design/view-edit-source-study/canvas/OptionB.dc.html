B · Source beside, in the split

Source is never a mode: it is always the split’s other side, as code editors do it (VS Code, Nova). ⌥⌘P becomes Show Source in Split View, for HTML and Markdown. The in-place Source Mode goes.

The page first, then its source [P]: you read the page and fix the text. Highlighted as A. Scroll-follow both ways [P] (amends DL-275’s caret-follow only): the side you scroll leads, the other keeps the same element at its top. Click on the page (with ⌥, so links still work) puts the caret on that element’s tag; the caret in source outlines its element on the page.

Getting in and out

Source Mode
Show Source in Split View ⌥⌘P
Previous Side of Split View ⇧⌘[
Next Side of Split View ⇧⌘]

⌥⌘P keeps its chord (DL-277) and is renamed [P]; it closes the split again. View › Source Mode goes. No new chord.

Editing and saving: the source side is the editor (DL-77), the page redraws from the buffer 250 ms after typing pauses (slice 1). Copy exact text from the source side.

Cost: A’s work, plus two-way scroll sync, page → source picking, the Markdown pair’s second view of one buffer, and folding rules. About two weeks.

The catch: the source needs 680 of width (two 340 sides), so the console narrows and, under about 1,464, the sidebar folds (DL-276) just to read a file’s text.

Decisions this reverses

· DL-278: “one file in two editable views is not part of it” (ENH-301). B builds ENH-301 for the source case.

· DL-167 Q3: Source Mode per document goes; the split is the only way to see a whole file raw.

Formatting bar (DL-266): on whichever side has the keyboard; its commands write into the one buffer, so both sides change.

Decks (DL-269): deck.md ⫼ Slides already uses the split, and its source side is the live editor. A deck’s raw text (the slide marker as typed, DL-296) has no place: a third side, or the chip only. [P] open

duo2 [P]: duo2 split <file> --with source (and with no option on an HTML file); split sync on|off; doc mode is retired, kept one release as an alias that opens the split.

How B handles the brief’s list

· In and out: ⌥⌘P, View, the tab’s menu. Editing and saving: the source side, DL-77. Sync: scroll both ways, caret ⇄ element. Review marks: raw on the source side, drawn on the live side. Highlighting: as A. Formatting bar: on the active side. Narrow: folds to a toggle. Themes: board “Highlighting”. Verbs: above. Cost: about two weeks.

· Best at: working on a page while watching it, which is what Nova and VS Code users expect. Worst at: a quick look at a Markdown file’s raw text, which now costs a split and the room it takes; and decks, whose source side is already taken.
