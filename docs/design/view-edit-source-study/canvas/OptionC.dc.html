Hover an element → the picker’s outline and a </> tag [P]; click it → that element’s source opens in a small editor under it, laid over the page [P]. ⌘↩ or Apply writes the change into the file at that element’s range and the page reloads; Esc cancels. Like DevTools’ Edit as HTML, but saved.

What it needs

· Each element on the page mapped to its exact range in the file: the HTML parse tree matched to the DOM in document order. A page whose script builds or moves elements (the chart here) breaks the match, so those elements can’t be edited this way.

· Duo’s own editor laid over somebody else’s page, inside its web view: styles, focus and keys must not leak either way, and DL-175’s content rules still hold.

· A small applied edit is a one-hunk save through DL-77, so Claude’s rewrites merge like any other.

Getting in and out: the hover tag; Edit Source… on the picker’s bar and the page’s right-click menu [P]; ⌥⌘U with an element picked. For the whole file, View › Source as in A.

Sync: none needed: the source sits on the element. Narrow: the editor is the page’s width, fine at 360. Themes: the inline editor takes Duo’s appearance over a page that keeps its own (DL-224), the one place both meet. duo2 [P]: duo2 html source <selector> reads an element’s source, html edit <selector> --text … replaces it; doc reveal <line> for Markdown blocks.

The split and decks: the pair stays as A draws it. A deck’s slide chip reveals its marker in place; nothing else changes.

Cost: three weeks or more, and the HTML half is research: the mapping and the overlay can each fail on real pages Claude writes (charts, generated lists). Best kept as a later step on top of A (ENH-311).
