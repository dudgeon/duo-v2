# Duo design docs

Start with the **design system**, `system/`. It's also published for Claude Design at https://claude.ai/artifact/QMapKeLYS3TVV36QKEc6MH. It summarises what's approved, built and pending: tokens, every component with its status, every surface, and screens of the app as built.

## What wins

1. `decisions.md` (DL-n).
2. The approved target screens in each handoff's `screens/`, unless a decision changed them.
3. The handoff READMEs, then the briefs.
4. Then the build plan, `legacy-requirements.md` (LR-n) and `stack-recommendation.md`.

`system/` restates the first three as built; where it disagrees with one of them, they win.

## Keeping it current

- **Tokens:** edit `build-handoff/tokens.json`, then run `python3 scripts/gen-tokens.py` (Swift) and `python3 scripts/gen-design-system.py` (the system). DuoChecks fails if either is stale.
- **A surface's status changes, or a component is added:** update `system/surfaces.md` and the component's README, then republish the changed files to the artifact.
- **New screenshots:** capture on sample data only, with `CLAUDE_CONFIG_DIR` and `DUO_SUPPORT_DIR` pointing at scratch folders (F-74).
