### Not asked, decided by default

- **App state location:** `~/Library/Application Support/Duo/` for the registry, caches, journals and the archive, not `~/.claude/duo/` (PR #1 §8). Keeps Duo's state out of Claude's tree and away from `claude purge`. Revisit if Geoff prefers legacy's location.
- **Attention columns:** three columns (needs you / in progress / done) with reason chips, per legacy-requirements §1 D2. Applied to the brief after design.
- **Single window** for v1, state designed window-aware (legacy-requirements §1 D10).
- **Obsidian spec, remaining questions** (`docs/research/obsidian-compatible-task-format.md` §5):
  - Q1: target Obsidian 1.13's public table/list views; the early-access Kanban is a bonus, not a promise.
  - Q5: no Duo-private keys in task files (`sessions` is a top-level list); if one is ever needed, flat `duo_` keys, never nested `duo.*`.
  - Q7: if `.obsidian/` appears inside a git repo, show a one-line hint; never write `.gitignore`.
  - Q8: document "open one level per topic as a vault" to avoid nested vaults.
  - Q9: read TaskNotes' `scheduled` and `priority` keys; never write them.
  - Q10 is a test, not a decision: run the spec's §4.7 check in a live Obsidian before locking the schema.
