# The List grouped by project — handoff (DL-341)

Geoff decided this on 2026-11-13 (DL-341; Q-546, Q-547), in chat on boards L1 and L2 of the all-projects-board study (study page https://claude.ai/artifact/KssyGmv9iLu75RAtsAnkHV, section "L List by project"; sources in `../all-projects-board-study/`, generated by `make_boards.py` + `boards_list.py`). His ask: "in the all projects >> list view, add an option to group by project and when list is grouped by projects, there should be a new session button per project". His answer on the button: "header right end; button could be more subtle; + button or other new session icon, and words 'new session' on mouseover". The order is as recommended.

## What to build

1. **Group ⌄ › Project.** The List's Group popup (`AllProjects/AllProjectsPanes.swift`, today one checked "Group By Recent" item and Show Archived) gains **Project**, with a check on the current one. The choice is remembered like `homeView`, in `DuoState` (`Live/HookEvents.swift`, beside `homeView`). View › Group Sessions By (Recent, Project) in `Navigation/Commands.swift`, as Sort Projects By is.
2. **Grouping.** In `AllProjects/SessionList.swift`, build per-project sections:
   - **Projects** go by their newest session's activity, newest first. If Q-541 (pins) later says yes, pinned projects come first.
   - **Sessions** inside a project go newest first: five, then "n more ›", which expands in place, using an `expandedGroups` key per project.
   - **Quieter projects · n:** projects with no session this week fold under this, closed by default. Inside the fold they're the same headers.
   - **Archived · n** stays last, as today, gated by Show Archived.
   - In a row, the project column shows the row's task (`▢ task`), or nothing. The project is already in its header.
   - The `3 need you ›` line (with the right pane hidden) stays as it is.
3. **The header row** (`AllProjects/SessionListView.swift`, a new `SessionListProjectHeader`):
   - **Layout:** 30 high, with a `rule`-coloured hairline above. In order: the fold chevron (⌄ or ›, toggling an `expandedGroups` key); the name in 13 semibold (`★ home` for Home); the folder in `monoPath` text2, truncating in the middle; the session count in text2 at 12.
   - **The +:** at the right end, 22×22, text2, no border, no fill.
   - **Hovering the +:** it widens leftward to "+ New session" (12 pt) on a `selected` pill with a 5 radius, text in `text`. It grows within the row, and nothing else moves.
   - **Tooltip:** "New session in ‹project›", then the folder.
   - **Accessibility:** the label is "New session in ‹project›" in every state.
   - A folded project keeps its +.
   - Clicking the header outside the + folds it, as `SessionListFold` does.
4. **What the + does.** It starts a Claude session in that project, or in that folder for a folder with no project file, and opens the project's page on it, as the sidebar's "+ New Claude Code session" does: `AppModel+StartSession.swift`. For a plain folder, Claude asks its own trust question, answered in Duo; Duo never writes trust.
5. **⌘T.** If a project's header or one of its rows is selected (the List's selection, `moveListSelection`), ⌘T starts the session in that project, and the header's + shows `⌘T` in text2 at 11 beside it. Otherwise ⌘T is DL-262's (Home, else `~/Documents`).
6. **Motion.** Folds use `.fold` (`withDuoAnimation`) as the List's folds do; the + widening has no drawn motion: use `motionChipIn` (stand-in, the nearest existing token; listed below) and respect Reduce Motion.

## duo2 (DL-71)

- **New:** `duo2 view list group recent|project`. It switches the List's grouping (View › Group Sessions By, the Group popup's Recent and Project items). Its catalogue row goes in `Sources/DuoControl/Actions.swift` beside `view home`, implemented in `Control/AppModel+Control.swift`. Regenerate `docs/cli/duo2.md` with `build/Duo.app/Contents/Helpers/duo2 help --markdown`.
- **Existing:** the header's + is `duo2 session new --project <p>`, or `--folder <path>` for a plain folder. Add "List project header +" to that verb's UI names.
- **Folds:** the per-project folds and "n more" are like the List's other folds, which aren't actions (`duo2 sessions` lists the rows), so they are `Parity.uiOnly`, as `SessionListFold` is today.
- **JSON:** `duo2 sessions --json` gains nothing. Optionally, `duo2 view home` reports the List's grouping.

## Stand-ins (not drawn; build as said, and record them)

- **The +'s widening motion:** `motionChipIn` until a motion token is decided.
- **Dark and Classic.** Build from tokens (`selected`, `rule`, `text2`, `monoPath`); a check in all three appearances is enough until a round draws them.
- **Narrow.** Under 520 (the List's two-line rows, Q-101), the header's folder hides first, then the count; the + always stays.
- **Filter.** With `Filter sessions` typed, the filter's own MATCHES view shows (F-181), not project groups.
- **Empty project.** A project with no sessions isn't listed (only projects with sessions are groups); the Board and the Projects pane list every project.
- **Selection.** A header can be selected with the arrow keys (so ⌘T can target it), but it isn't part of the multi-select (DL-247): ⇧- and ⌘-click on a header do nothing.
