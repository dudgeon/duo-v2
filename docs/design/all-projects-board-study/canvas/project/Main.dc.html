All projects' Board: organise by what's happening, not by Home
Geoff, 2026-11-13: the Board wastes space (a tall stack under Home, white space to the right); many users don't keep a Home folder; the one New session control doesn't say which project it starts in. A study, nothing built. Sample data only (the home-evolution study's names).
Why it looks like that (board 01)
The Board packs whole folders into at most three columns (DL-83, DL-129). Home's ★ tile and every project sitting directly in Home are one unlabelled column, so it is always the tallest; a folder with one project is a short column beside it. A wider window only makes the three columns wider (526 pt each at 1900): nothing new fits. Folders outside Home sit under the whole grid, below the tallest column.
The directions
A · Folder bands (board A). The smallest fix: each folder is a row of tiles across the width, Home is one band like any folder, more tiles across when the window is wider.
B · By activity, recommended (boards B1, B2). Pinned, Now, Today as tiles; This week as rows; Earlier and Archived folded. The folder becomes a line on the tile. Group ⌄ keeps Folder (A's bands) and None.
C · Flat, with pins and a folder filter (board C). One grid by recency; folders are chips that filter.
D · A projects table (board D). The broad rethink: a sortable table instead of tiles.
In every direction (board T)
+ New session on every tile: a quiet last row, in the tile's own frame, so there's no doubt which project it starts in. The tooltip names the project and its folder; ⌘T starts one in the tile that has the keyboard focus. The verb, duo2 session new --project, already exists.
