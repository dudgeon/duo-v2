## The definition's build inputs

A template's yaml block tells build where its layout comes from. Lines Duo writes carry `# duo`.

```yaml
layout: Title + Bullets      # an existing layout of the source (kept as it is)

from-slide: 3                # a slide of loose boxes, promoted into a new layout
source: ../other.pptx        # (optional) take the slide from another pptx
slots:
  value:    {kind: number, max: 6, shape: Value}                    # the box named Value becomes idx 13
  footnote: {kind: text, max: 60, optional: true, box: 66 467 800 20, size: 11}   # a box of its own: a new placeholder
renamed: {context: note}     # a slot this template used to have (DL-293)
```

- The frontmatter `source: <pptx>` is the deck theme, masters and layouts are copied from; only the layouts used are kept. Without it, an existing `<pack>.pptx` is amended in place (what `deck import` does).
- **Promotion:** the slide's boxes named by `shape:` become placeholders (the `title` slot is a real title placeholder, idx 0; the others are `body` idx 13 and up in slot order, or the idx already written), each with that box's first paragraph and run properties as the layout's list style; every other shape becomes layout decoration (pictures bring their media); the footer, date and slide-number placeholders come from the layout the slide was on. Build says which shapes became decoration, and which of those carry text.
- A slot that has `box:` and no `shape:` is added as a placeholder wherever it is declared (promoted or existing layout). `optional: true` means a slide may leave it out with no notice.
- Build rewrites each `layout:`, `fingerprint:` and slot `idx:` in place and leaves every other line alone. Running it again gives the same bytes and no change to the definition.
- Cleaned in the pptx: `lastModifiedBy` is "Duo", `app.xml` says 0 slides with no title list, no thumbnail, comments, printer settings or sections, and a 16:9 `sldSz` has no `type`.
- Checked against the pptx (problems stop the write): unknown idx (`bullets.body: unknown idx 9; layout "Title + Bullets" has 0 (title), 1 (body)`), kind against placeholder type (`two-column.left: kind image doesn't fit placeholder idx 1, which is type body`), bullets on a `buNone` placeholder, a missing layout (names the ones there are).
- Fit of the limits (reported, still written): see below.

### Measured fit (Q-379)

`TemplateFit` sets the slot's text in CoreText in the placeholder's font and size, in its box minus the insets (and a bullet's hanging indent), and counts lines against the lines the box holds (line height of the font times the layout's line spacing, less the space before each paragraph).

- `deck check` adds `slide 3 (kpi), label: does not fit: 2 lines at 18 pt; the box holds 1`, for text, number and bullets slots whose text passes the character limits. Character limits stay as they were.
- Build and specimen add `limit too high: 200 characters at 18 pt take 3 lines; the box holds 1; largest that fits: 74` (bullets: `4 points of 60 characters at …`), found by bisecting on the sample text.
- A font not installed here falls back to a system font of similar metrics (a serif to Georgia, a monospace to Menlo, a sans to Helvetica Neue), and the message ends with `(Inter isn't installed here; measured in Helvetica Neue, widened 7% for Inter)`. Inter is widened because it sets about 7% wider than Helvetica Neue; that factor is a rule of thumb, not a measurement.
- PowerPoint's shrink-on-overflow (`normAutofit`) is not applied: Google Slides and a freshly exported file show the nominal size.
- Not measured: image and table slots, nested bullet levels (measured at level 1), mixed fonts inside a slot.

### Rename map and migrate (Q-385)

```
$ duo2 deck check decks/a.md
decks/a.md:16: slide 1 (kpi): renamed "context" to "note" in growers.md; run duo2 deck migrate
1 problem
$ duo2 deck migrate --dry-run
--- decks/a.md
+++ decks/a.md
@@ -13,6 +13,6 @@
 ## label
 Of rows done
 
-## context
+## note
 Up from 61%.
 
1 slot heading would be renamed in 1 deck (dry run: nothing written)
```

`migrate` walks the project (found from the current folder, skipping `.git`, `.duo`, `templates` and the protected macOS folders), takes decks whose `template:` is the pack (`--pack` limits it), and rewrites `## old` to `## new` only on slides that don't already have `## new`. It prints a unified diff per deck, then writes unless `--dry-run`. Nothing is merged: a slide with both headings keeps the error.

### Import (M3b, Q-398)

```
$ duo2 deck import grower-update.pptx --pack growers          # no plan: the survey
grower-update.pptx: 8 slides in 7 groups, compared with the growers pack
  G1 slide 1 on Title: ctrTitle@0 subTitle@1
      best: title (exact)
  G3 slides 3, 4 on Blank (loose boxes): …
      best: kpi (loose boxes: 4 text boxes for 4 text slots; map them in the plan)
  G4 slide 5 on Blank (loose boxes): …
      best: none in the pack; a new template, or amend one
near groups (candidates to coalesce into one template with an optional slot):
  G3 ~ G4: G4 has 1 extra box (text); positions differ by up to 6 pt
fonts: Avenir Next is not in Google Fonts (closest: Nunito Sans)
2 PowerPoint comments will come in as Review comments
```

`--json` gives the same survey for Claude. Matching is by placeholder fingerprint (`exact`; the template's optional slots differ; the slide has fewer or extra boxes). Loose boxes can't be matched by position, so the survey counts text boxes against the template's text slots.

The plan is a small YAML subset (`DeckImportPlan.swift` documents it):

```yaml
groups:
  - slides: 1
    template: title
  - group: G3, G4                  # the survey's ids, or slides: 3, 4, 5
    template: kpi
    map: {Footnote: footnote}      # optional: box name -> slot
    amend:                         # add slots to an existing template (optional unless optional: false)
      footnote: {kind: text, max: 60, shape: Footnote, from-slide: 5}
  - slides: 7
    template: chart-slide
    new:                           # a template the pack lacks: from-slide + slots with shape:, or layout:
      from-slide: 7
      slots:
        title: {kind: text, max: 40, shape: Title}
        chart: {kind: image, shape: Rows chart, aspect: 2.2}
  - slides: 8
    template: closing
    new: {layout: Title Only}      # slots come from the layout's placeholders, limits from the fit
```

Run with `--plan`, Duo (1) edits the definition (`amend` becomes a slot line with the box and size read from the donor shape written as `box:` and `size:`, so the definition stands alone; `new` appends a section, with a `source:` when the pptx isn't the pack's), (2) builds the pack, (3) converts every slide, (4) writes the deck, checks it and prints the report. The plan must cover every slide; `--out` names the deck (default: beside the pptx; it refuses to overwrite).

Conversion rules:
- A placeholder's text goes to the slot with the same idx. A loose box goes to the slot the plan's `map` names, else the slot whose box is nearest (within 60 pt), else a required slot still empty takes the nearest shape of its kind. Bold runs become `**bold**` only when the paragraph has plain runs too.
- Bullets keep their level (clamped to the template's); several paragraphs in a text slot join with a space (the P0 limitation).
- Speaker notes become `> [!note]`. A box that maps nowhere is added to the notes as `Not placed from the original slide: …` and counted in the report.
- **Comments (DL-290):** legacy (`commentAuthors.xml`) and modern (`authors.xml`, with replies) comments become `{>>@sam-rivera 2026-10-20 #c1: which farms?<<}` on their own line right after the slide marker; replies are `#c2.1`. A modern comment that targets a shape (`spMk`) goes in the slot that shape became.
- **Charts:** the slot gets `![Chart: Rows chart](assets/<deck>-7-chart.png)`, a grey placeholder picture that Duo writes, and the chart's series go to the notes (`- Rows: Week 1 120, Week 2 180, Week 3 240`). Drawing a chart needs the deck viewer's renderer (WebKit); the report says so.
- Pictures are copied to `assets/`. Tables become GFM tables. The source pptx is never written (checked by bytes).

## Judgement calls and limits

- **Loose-box promotion needs `shape:` per slot.** Names come from the inventory. Nothing guesses which box is the value; that stays Claude's question to the user (M2).
- **Build is a package rewrite, not an Office conversion.** Masters and layouts are copied as XML and re-serialised (attributes in sorted order, same content). Opened with python-pptx here; not opened in PowerPoint, Keynote or Google Slides.
- **Decoration with text is burned into the layout** (a "Draft" stamp in a promoted slide would be); build lists those so Claude can move the shape into a slot or drop it.
- **A promoted slide's picture decoration** copies the media into the pack; a very large source image makes a large pack.
- **Near groups** use 36 pt and at most two extra boxes; both are constants in `TemplateInventory`.
- **Import never merges on its own.** The survey lists near groups; the plan is where the merge is written, and the skill tells Claude to put each one to the user.
- **Auto limits:** `new: {layout:}` fills `max` from the fit measure; promoted and amended slots take the limits the plan gives (none if omitted).
- **Fit is measured only where the pack's fonts allow:** here Inter isn't installed, so decks on Inter are measured in Helvetica Neue widened 7%.
- The skill's Decks section now describes the template steps and `migrate`; it names only registered verbs (a check scans for it).
- `docs/cli/duo2.md` rows for the seven new verbs were added from the registry by script because the full `duo2` build was queued behind another session's hold on the GPU lock; run `duo2 help --markdown` to confirm it matches.
