Home, projects and tasks

How Duo should model your workspace: Home holding many projects, topics as an optional folder layer, and tasks under projects that sometimes hold sessions. Three questions, one big and two smaller. Click one card per question, add a note if you like, then "Copy my picks" and paste it back.

Two layers are optional and shouldn't be enforced: the topic above a project, and the task between a project and a session. A project can hold sessions directly, tasks, or both. A task can exist with no session at all; it's a to-do first.

The open part is where tasks live and how a session belongs to one. That decides whether projects "move up a level" only in Duo's lists or on disk too.

How Duo does it today

Sessions
Every session in Claude's logs, on every launch (DL-82, built since this page first went up). No setup needed; folders are grouped by the folder they sit in (DL-83).
Home
Optional, chosen any time (File › Choose Home Folder…). It's the container of the projects you track, with HOME.md at its top (DL-85). Move into Home… brings a project in with its sessions.
Topic
Worked out on the fly from the folder a project sits in; nothing stores it. Projects directly in Home sit in an unlabelled first column; outside Home, columns are labelled by path (~/repos). That's T1 below, already built as the default.
Project
Any folder with a PROJECT.md, found up to three levels down. Projects can't contain projects.
Session
Belongs to the deepest project folder it ran in, or to the project you filed it in (DL-64).
Task
Format decided, UI parked: one Obsidian-style file per task in tasks/ (DL-6), whose sessions: line lists its sessions (DL-13). Nothing reads them yet (DL-25).
Group
Sessions you bundled by hand. Duo-only, nothing on disk (DL-24). A task with sessions is very close to this.

The constraint that matters: Claude files every session by folder

Each session belongs to the folder Claude ran in. Its transcript sits in a bucket named after that folder, Claude reads CLAUDE.md from that folder and every folder above it, claude --resume lists that folder's sessions, and /cd moves a session to another folder. So the real choice is whether a task is a note that points at sessions (the sessions run in the project folder) or a folder the sessions run in.

True whatever you pick

  • Every session is visible and usable, Home or not (DL-82). Home is optional and can be chosen any time; Duo writes HOME.md if it's missing.
  • Projects directly in Home show on the map, in a first column with no label; folders outside Home are grouped by their parent folder (DL-83). Built.
  • Moving a project into Home keeps its sessions (DL-85): the folder and Claude's records move together, undoably.
  • Topics never become required. A project with no topic is normal.
  • Forks still fold into one thread row under their session. Threads don't change.
  • A task row takes the state of its most urgent session, like a group row today, so lists stay sorted by what needs you (handoff §2.1).
Question 1 · the big one

Where do tasks live, and how does a session belong to one?

Each option shows the same example on disk and in a project's session list. The Duo side is illustrative only; the real look goes to the design queue.

ATasks are notes that point at sessionsRecommended

A task is a Markdown file in the project's tasks/ folder. Its sessions: line lists the sessions working on it. Every session still runs in the project folder, so Claude sees one project. This is DL-6 and DL-13 as already decided, finally shown.

On disk

├─ PROJECT.md
├─ tasks/
│  ├─ launch-copy.md   sessions: [a1f…, 7d0…]
│  └─ ab-test-plan.md  no sessions yet
└─ src/ …
every session runs in pricing-page/
In Duo

For

  • A task can exist with no session, which matches "tasks sometimes contain sessions".
  • Claude, Duo and Finder agree: one project, one folder, one CLAUDE.md.
  • Moving a session between tasks just edits a line, instantly. Nothing moves.
  • Tasks open in Obsidian as ordinary notes (DL-6). Nothing already decided is reversed.

Against

  • claude --resume outside Duo still lists every session in the project, with no task grouping.
  • A task's own files have no home of their own; they sit in the project.
  • Writes tasks/*.md into the project. In a shared Git repo that shows in diffs (C-7).
Do projects move up? In Duo's lists, yes: a project lists tasks and loose sessions. On disk, nothing moves.Build: medium. Read and write task files, task rows (reusing group rows), New Task, Add to Task, duo2 task ….
BTasks are folders that sessions run in

A task is a subfolder of the project with a TASK.md. Its sessions run inside it, so Claude files them under the task. Sessions that belong to no task run at the project's top level.

For

  • A task has a place for its own files, beside its sessions.
  • claude --resume in a task folder lists only that task's sessions.
  • The structure is plain in Finder and survives without Duo.

Against

  • Every to-do needs a folder, even a one-line task with no session.
  • Moving a session between tasks is a real move, done on its next resume (DL-64).
  • Task folders land in repos. That's worse than C-7, and deeper paths too.
  • Partly reverses DL-6's "one file per task". Obsidian sees folders, not task notes.
Do projects move up? Yes, on disk too: the project becomes a container and the task becomes where work runs.Build: large. Discovery, attribution to the task folder, task navigation, moves through the migrator.
CAny folder, any depth: projects nest

Drop the fixed levels. Any folder with a PROJECT.md is a project, and projects can hold projects. A session belongs to the deepest project it ran in. Topic, project and task are just names for how deep you are.

On disk 
~/work/

│  ├─ checkout/      PROJECT.md
│  │  └─ exec-review/ PROJECT.md: acts as a task
│  └─ refunds/
└─ pricing-page/

For

  • One idea instead of three. Nothing is enforced and any depth works.
  • Projects really can move up: any project can gain children later.
  • A topic can have its own PROJECT.md and sessions if you want.

Against

  • A to-do with no folder doesn't fit, so tasks as notes would still be needed alongside.
  • The map's columns and the session lists become a tree. That's a large new design.
  • "Is this a project or a task?" has no answer, so lists and search lose a stable shape.
  • Reverses CONS L2 (projects don't nest). The migrator's moves and merges get harder.
Do projects move up? Any level can, at any time.Build: largest, and design-bound: tree navigation, nested attribution, nested moves.

Why A: your description treats a task as a to-do that sometimes gathers sessions, and A is the only option where that is the native shape. It keeps Claude's folder and Duo's project the same thing, so nothing surprising happens outside Duo, and it builds what's already decided. B is the fallback if you find tasks need their own files more often than not. It can come later as "Make this task a folder", without undoing A.

Question 2

What makes a topic?

Whichever you pick, root projects show in the unlabelled first column, and Elsewhere stays for folders outside Home.

T1An optional folderRecommended

A folder in Home with no PROJECT.md that holds projects is a topic, named after the folder. Today's rule, minus the root-project bug.

On the map
pricing-page2 need you
q4-planningidle
Payments
checkout1 working
refundsidle

For

  • Finder and Duo agree. No new file.
  • Almost no build.

Against

  • Changing a project's topic moves its folder (the migrator carries its sessions).
  • One topic per project.
T2A line in PROJECT.md

topic: Payments in the project's frontmatter. Folders stay flat in Home; the topic is a label.

On disk 
checkout/PROJECT.md
---
topic: Payments
---

For

  • Retopic by editing a line; nothing moves.
  • Could later allow more than one.

Against

  • Finder doesn't show it.
  • Folders you already nested would be ignored.
T3Folder, unless the line says otherwise

T1 by default; a topic: line in PROJECT.md wins when present.

For

  • Works with any existing layout.
  • Retopic without moving when you'd rather not.

Against

  • Two sources of truth: "why is this project here?"
  • More to explain.
T4No topics

The map is one set of projects, sorted by what needs you. Projects in subfolders are still found, just not grouped.

For

  • Simplest model of all.

Against

  • Nothing to group many projects.
  • The map's column layout (DL-22) needs a redesign.
Question 3

Do groups survive once tasks exist?

A group is sessions bundled by hand, held by Duo only. A task with sessions is nearly the same thing, so with A or B there would be two ways to bundle sessions.

G1Groups become tasksRecommended

"Group sessions" becomes "New task from sessions": it writes a task note listing them. Existing groups turn into tasks once, with undo.

For

  • One way to bundle sessions; one word to learn.
  • Bundles show outside Duo.

Against

  • Every bundle writes a file into the project (C-7).
G2Keep both

Groups stay as quick Duo-only bundles; tasks are notes with goals and status.

For

  • Bundling never touches the repo.

Against

  • Two similar rows in every list, each with its own menu. The confusion Q-27 is about.
G3Groups stay, and can be made tasks

As G2, plus "Make a Task" on a group writes the note and replaces the group.

For

  • Light bundling, with a path to a real task.

Against

  • Still two concepts, plus a conversion step.
