What stays as decided

  • One file per task, tasks/<slug>.md, status one of open, in-progress, waiting, review, done, dropped (DL-6, the format doc §4.2).
  • Duo edits only the lines it owns, surgically (§4.1, DL-93); never writes .obsidian/; never writes a .base unless asked (DL-20).
  • The task menu (DL-115), New Session in Task (DL-112), the five session states and their glyphs.
  • Side panes keep their width; the middle flexes (DL-129).

What Obsidian does today (verified 2026-10-07)

  • Bases Kanban is public since Obsidian 1.14.4 (2026-10-05). A .base view type: kanban groups notes by one property; dragging a card writes that property in the note. groupOrder fixes the columns. This is exactly Duo’s shape: one note per task, lanes = status.
  • Bases stores no manual card order: cards follow the view’s sort.
  • The Kanban plugin (2.7M installs) keeps a whole board in one note: lanes are ## headings, cards are - [ ] lines. It rewrites the whole file on every change and can’t read one-note-per-task. Its last release was May 2024; its author is looking for maintainers.
  • TaskNotes (2M installs) is a kanban over task notes too. Its manual order is a tasknotes_manual_order key written into each note.
  • Tasks has columns over checklist lines, not notes; Dataview has no board; Projects is archived.
