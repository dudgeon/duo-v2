Removing a column that holds tasks asks where they go (a Duo question, never an alert), then writes each task’s status. An empty column just goes (⌘Z brings it back).

Absent means the default five. Duo adds the key the first time you change columns, and edits only its lines afterwards.

Rules [P]

  • A column is a status. No column exists only in Duo’s view state. Set Status ▸ (DL-115) lists the project’s columns, then dropped.
  • Unlisted statuses still show, as an extra lane at the end in text2 with Keep as Column in its menu (that adds it to lanes). Nothing is ever hidden or rewritten silently.
  • Renaming a column would rewrite every task in it, so it isn’t offered now. Remove then add does the same, and asks first (ENH).
  • Duo’s meanings stay with the words: done and dropped close a task (completed written); waiting takes waiting_on; anything else counts as open work.

Obsidian [P]

  • “Add Obsidian Board” writes groupOrder from lanes (Q-121 as answered: pinned).
  • When the columns change afterwards, the board header shows “Obsidian board is out of date · Update”. Update Obsidian Board rewrites only the groupOrder lines Duo wrote; everything else in the base stays the user’s.
  • A user who reorders columns in Obsidian changes only the base. Duo doesn’t read it back (one-way: lanes is Duo’s list).

Where else could the list live?

  • PROJECT.md lanes: (proposed): travels with the folder, visible in Obsidian’s Properties, one plain list.
  • .duo/: invisible to Obsidian and git-ignorable, but the project’s workflow would live outside its files (against ENH-228’s “files are the schema”).
  • The .base file: only exists when asked for (DL-20), and is Obsidian’s.
