How the tree behaves

PProjects that need you rise to the top of the tree, under ★ home; the rest keep the map's order, topics dropped to save height. Inside a project only the open branch shows its folder.

PThe open project's sections are today's (PINNED, NEEDS YOU, OPEN, TASKS, OTHER SESSIONS, Archived), indented 28 under the thread rule, with their own folds. Opening another project closes this branch and opens that one.

PNo ‹ Projects row, no slide: the list is always there. ⌃⌘S hides the whole pane, as today.

What it costs

About 100 points of height above the project's own sessions (★ home and the projects that need you), and 28 of width off every row: at the 240 minimum a session name gets about 150. The approved order (PINNED first, DL-217) moves below the projects, so that decision reopens.

With 30 projects the branch can sit far down; the “5 more” fold keeps the rest to one row, which means the list is not the whole list.

Why it isn't recommended

It is what the first user named (“as I can in CC or ChatGPT”), but Duo's sidebar already does a lot more than a chat list: tasks, needs you, threads, files. A gives the same list one click away and leaves that sidebar alone.
