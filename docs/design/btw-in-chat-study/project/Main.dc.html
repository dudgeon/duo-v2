/btw in chat: what Claude Code does, why chat falls back to the terminal, and the questions
Run headless on 2.1.284 (the work Mac’s pin) and 2.1.323 (newest here), on the chat spike’s mock API with a scratch config; no login, no tokens, nothing on screen. Research: docs/research/btw-in-chat.md. Records F-688 to F-690, Q-550 to Q-554, C-185, ENH-353.

It runs at once, even while Claude works: it never queues. The panel takes the input box’s place and the footer’s: there is no prompt to type into until Esc. Claude’s turn keeps streaming above it. At the prompt, the panel lists earlier side questions: ⇧←/→ to browse · c to copy · f to fork · x to clear history · Esc to close. Bare /btw prints Usage: /btw <your question>.
What it leaves for Duo to read
Transcript: nothing. Not the question, not the answer, on either version.
Hooks: no UserPromptSubmit. One SubagentStop when the answer lands, with agent_type: "", an agent_id, the answer as Markdown in last_assistant_message, and an agent_transcript_path that is never written. No SubagentStart before it.
Screen: the question, Answering…, the answer’s text and the footer’s keys.
Prompt history (history.jsonl): the typed /btw … line.
Why chat falls back
1. The screen reader finds no input box under the panel (its top is a ▔ rule, and the footer is gone), so it reads unknown: ChatScreen.swift:454.
2. Unknown for 0.5 s (ChatSession.swift:272) falls back, and because /btw was just sent from chat the bar is named: “/btw opens in Claude Code’s own screen. Esc closes it and brings chat back.” (ChatSession.swift:434).
3. That’s by design today: /btw is on chat’s list of commands with their own screen (ChatScreen.swift:87, F-173), and the / menu labels it “Opens in the terminal” (ChatComposerView.swift:159).
Two more faults on the way
A queued bubble that never clears. Sent while Claude works, the /btw is shown as your message, “Queued · Claude reads it when it’s ready” (ChatSend.swift:49). Claude’s turn never reads it, and nothing echoes it, so it stays queued; a reload drops it.
The side answer finishes an agent’s card. With an Agent step running, /btw’s SubagentStop (no start) marks that card done with the side answer as its result (ChatLog.swift:527–533).
