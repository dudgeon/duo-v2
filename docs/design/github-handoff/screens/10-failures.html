10 · When it fails: one question each, in plain words, never git’s raw output
In Duo’s own question look (DuoQuestion, never a system alert). Each names what happened, what was and wasn’t changed, and one way forward. git’s and gh’s own words are kept behind a Details disclosure for whoever helps, not shown first (legacy showed raw stderr). Duo classifies by exit code and known messages; anything unknown says “GitHub refused the push” with the details. [P]

Duo needs the GitHub CLI for this

Listing your repos and making a fork use GitHub’s own command-line tool, gh. It isn’t on this Mac. You can still paste a repo’s link: Duo copies and pushes with git.

Paste a LinkInstall in a Shell…
No gh (only when a step needs it). Install in a Shell opens a Duo shell tab with brew install gh typed, not run; without Homebrew, the GitHub CLI’s download page.

Sign in to GitHub

Duo never sees your password or keeps a token. The GitHub CLI signs you in through your browser and keeps the sign-in in your Mac’s keychain, where git uses it too.

CancelSign In in a Shell…
Signed out (gh signed out, or git had no credential). Opens a shell tab running gh auth login --web --git-protocol https, then gh auth setup-git; Duo retries when it ends.

Duo can’t see acme/website

It may be private, the link may be wrong, or your GitHub account (geoffd) hasn’t been given access. Ask the repo’s owner to add you, or sign in with another account.

Switch Account…Open on GitHub
No access or not found: GitHub answers the same for both, on purpose. Signed out, the title is “Sign in to see acme/website” and the button is Sign In.

acme needs you to authorize single sign-on

Your organization requires single sign-on for the GitHub CLI. Authorize it on GitHub once, then try again.

CancelOpen GitHub
SAML SSO: GitHub’s “Resource protected by organization SAML enforcement”. Common at companies; legacy’s research flagged it.

main is protected on acme/website

Changes to main go in through a pull request. Duo can move your 2 commits to a new branch, geoff/pricing-copy, push that and open the pull request. main here goes back to match GitHub.

CancelMove to a Branch and Push
Protected branch (GH006, or a rule found ahead). Rare: projects from GitHub start on a branch. git switch -c, then main reset to origin/main only after the new branch holds every commit.

GitHub has newer work on geoff/pricing-copy

Someone pushed to this branch (or you did from another Mac). Get it first, then push.

CancelGet Latest and Push
Rejected, not fast-forward (“fetch first”). Never a force push.

You can’t push to acme/website

GitHub says your account, geoffd, can read it but not push to it. If you should be able to, check with the repo’s owner. Or Duo can push to your own copy (a fork) and open the pull request from there.

CancelFork and Push
403 on push when access wasn’t known ahead (board 7 B). Names the account git used: a stale keychain account is a common cause. Without gh: “…Install the GitHub CLI to make a fork, or ask the owner for write access.”

Duo couldn’t reach GitHub

Check you’re online and try again. Nothing was changed.

OKTry Again
Offline or timed out (every network step has a time limit). For the background fetch, never a question: the line says “can’t reach GitHub”.

GitHub refused files that look like secrets

GitHub’s secret scanning found something like a password or key in content/plans.json and refused the push. Nothing was pushed. Remove it (Claude can help), then push again.

Show DetailsAsk Claude to Remove It
Push protection (GH009). Files Claude wrote can trip it. Never offer to bypass.

Tell git who you are

Commits carry a name and email, and this Mac has none set for git. They show on GitHub next to your changes.

CancelSave for This Repo
No git identity. Name and email fields (prefilled from GitHub when gh is signed in). ENH-39.
