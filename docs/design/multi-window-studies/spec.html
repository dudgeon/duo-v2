Multi-window Duo

The spec for Geoff's direction: independent windows, each optionally pinned to one project and tinted. It covers what changes, the tradeoffs and the size, then the decisions still open. Pick an option on each decision, add a note if you like, and press Send to Claude. The boards are on the studies canvas.

The model

Independent windows

Every window is a whole Duo: All projects and inside a project, any project. File › New Window ⌥⌘N.

Pinned to a project

Optional. A pinned window shows one project, has no All projects, and keeps it through relaunch.

Tinted

Optional. The window's light chrome takes a tint so you can tell windows apart. The console and the needs-you orange never change.

What has to change

Duo today is one window. One AppModel holds both the app's data and about 45 properties of that window's state. There is one shared editor, HTML viewer and deck viewer. Each terminal and browser tab is a single view that moves between panes. 24 places look up "the window", 16 of them by its title.

Tradeoffs and risks

  • This is the model legacy Duo took three releases to land, because anything could appear anywhere. The rules below give every live view one home: a terminal, an editor, a web view. That removes most of the cost, but not all of it.
  • A document edited in two windows is the costliest part if both must be editable. Read-only plus Edit Here (decision 7) keeps one writer and needs no merging.
  • Typing at once. The terminal in window 1 and chat's composer in window 2 both write to one prompt. Chat already mirrors the prompt line; the build must test both at once.
  • Tints and the one accent. The needs-you orange falls to about 4.2:1 on a full tint, so the chip gets a white fill on tinted toolbars. No tint may be orange or red. Tints are new tokens.
  • Pinned windows and jumps. Search, the peek, notifications and duo2 open have to respect a pin (decision 3), or the pin breaks the first time you search.
  • Splitting the model touches 300 or more references. It is done in one slice with no visible change, proven by DuoChecks and every check-ui state unchanged.
  • Scope. The build plan's §3a lists multi-window as deferred past v1. Building it now needs a logged reason.
