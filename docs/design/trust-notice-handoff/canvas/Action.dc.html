Trust This Folder… always asks first, and says exactly what changes [P]
A Duo question through SheetCenter (DuoQuestion), hung from the toolbar, never a system alert. Trust Folder is the default button (Return), Escape cancels. It is shown only after you press Trust This Folder…, or when duo2 asks (Q4).
Q1 A (recommended) · Duo writes the one key, after this
The box shows the file and the one change, in mono: the path as Claude keys it (real path, the repository's top folder). If the session runs in a subfolder, the first line says "checkout (the repository's top folder, which holds api/)". With CLAUDE_CONFIG_DIR set, the box names that folder's .claude.json.
Q1 B · Claude Code's own question, in a tab
A tab opens beside the session running claude in the folder (with a minted --session-id), selected, showing Claude Code's own trust question. On 2.1.303 its default is "No, exit": you move down to "Yes, I trust this folder" and press Return. Duo sees the prompt arrive, ends that process and closes the tab. No turn runs. Claude's question text here is illustrative; the build shows Claude's screen as it is.
Why A is recommended: one step instead of three, the change is shown before it's made, and it doesn't start a second Claude. Why you might pick B: Duo never writes Claude Code's file (today it never does; trust is never copied on a move, FR-7.10.10).
Both: only this folder; Cancel changes nothing; the running session isn't restarted; works the same on 2.1.219 (same file and key), though there the notice doesn't appear.
