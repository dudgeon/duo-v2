Trust this folder: when /fork says "Workspace not trusted" (Q-219, DL-227)
Claude Code 2.1.303 checks trust again when /fork starts its background session, and that check honours a trusted parent only down to a git repository's top folder. The session's own screen checked once, at start, when the folder wasn't a repository yet. So a project under a trusted Home that became a repository during the session can't fork. Claude Code 2.1.219 doesn't have this check: there /fork works and the notice never shows.
What Duo would write, exactly (checked on 2.1.219, 2.1.303, 2.1.304)
One key, in Claude Code's own file: ~/.claude.json (or $CLAUDE_CONFIG_DIR/.claude.json), projects["/Users/you/claude-home/checkout"].hasTrustDialogAccepted = true. The same file and key on all three versions. It is what Claude Code writes when you answer its own "Yes, I trust this folder".
Which folder: the repository's top folder (where Claude's check stops), by its real path, no trailing slash. Nothing above it, nothing beside it.
Nothing else changes. If the entry exists (Claude makes one with false at each start), only that value flips; if not, the entry holds that key alone. Duo takes Claude's lock (.claude.json.lock), re-reads, writes a temp file beside it and renames it over, as Claude does. Claude merges by key, so a running session keeps Duo's change.
Effect: the next /fork in the same session works, with no restart (Claude re-reads the file on each check).
Rules (not questions)
Never silently. Only after your OK in a Duo sheet that names the folder, the file and the change (board 2). No setting turns it into an automatic step.
Offered only for this case: Duo reads Claude Code's exact line on the session's screen, the folder in it is the session's own (or its repository's top), and a folder above it is already trusted in Claude Code. A folder Claude Code never trusted gets the words, not the button: "Run claude there once and answer its trust question."
Once per folder. After it's trusted, the notice can't come back for that folder.
Questions · Geoff picked A, A, A, A (2026-10-20, by buttons; DL-229)
Q1 · The action. What does Trust This Folder… do?
A (recommended): after the sheet, Duo writes that one key itself. Exact, shown first, works in the open session at once.
B: Duo opens a tab running claude in that folder, so you answer Claude Code's own trust question ("No, exit" is its default on 2.1.303), then closes it. Duo writes nothing, but it's a second Claude start and an extra keypress.
Q2 · Where, in a terminal session.
A (recommended): a bar under the terminal, like the ended bar: next to the line Claude printed and the prompt you're typing in.
B: a bar over the terminal, under the tab strip, like the editor's notices.
Q3 · After trusting.
A (recommended): the bar says it's trusted and offers Fork Again, which types your same /fork line again.
B: the bar says it's trusted and to run /fork again; you type it.
Q4 · duo2 (DL-71). duo2 session trust-folder <id>
A (recommended): always shows the sheet in Duo for you to answer; no --yes. Claude can ask, but can't trust a folder for itself.
B: --yes skips the sheet, like issue close --yes.
