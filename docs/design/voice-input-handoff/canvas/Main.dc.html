Voice input: a mic for chat, and for the terminal

Geoff, 2026-10-30 [G]: “a mic button in the duo chat composition ui (and the terminal ui if possible/practical); leverage the on-device transcription service, not include a custom model.” Everything else here is [P].

The engine [G]

Apple’s on-device recognizer. SpeechAnalyzer with SpeechTranscriber (macOS 26). Duo needs macOS 26, so every Mac that runs Duo has it. When SpeechTranscriber has no model for your language, Duo falls back to SFSpeechRecognizer with on-device recognition required.

Nothing downloaded by Duo, no model in the app. macOS fetches its own speech model the first time, which Duo shows as “Getting the speech model from Apple”.

Measured Oct 12: 13.5 % of words wrong on technical prompts (Parakeet was 10.2 %), 2.2 % on your own voice reading plain sentences (level with Parakeet). Text arrives about 0.1 s after you stop.

Duo asks for permissions now [P]

Duo has asked for none so far (F-53, F-54). Voice input needs the microphone, and Speech Recognition only if the fallback runs (SpeechTranscriber needed no speech prompt in the Oct 12 tests).

  • Asked only when you first press the mic, after a Duo sheet says why. Never at launch.
  • Never in scripted or isolated runs: they say the microphone isn’t available.
  • No audio is kept: nothing is written to disk, nothing leaves the Mac.
  • Release builds get the audio-input entitlement and a usage string.
Where the words go [P]
  • Chat: at the caret in the composer. Words still being heard show grey and settle to ink as Apple confirms them. One ⌘Z takes back one dictation.
  • Terminal: straight into Claude’s own prompt, a phrase at a time as Apple settles each one, each a bracketed paste (as duo2 send text). No bar, no Paste step. The mic sits on Claude’s input box’s bottom rule, where typed text never goes (chosen, DL-261); nothing is added to the console strip.
  • Duo never presses Return. You send it.
Keys and duo2 [P]
  • ⇧⌘D, Start Voice Input (Edit menu, beside macOS’s own Start Dictation). Free in DL-34’s map; needs a DL. Tap it to start and tap again to finish; hold it past 0.3 s and it’s hold-to-talk, ending when you let go.
  • Esc discards in chat. In the terminal Esc stays Claude’s.
  • duo2 voice start|stop|status [id] does what the mic does (it needs the microphone, so isolated runs refuse it).
  • duo2 voice file <audio> [id] transcribes a file into the session’s prompt: the scripted twin the checks use.
The work Mac [P]

It runs macOS 26 or later (Duo’s minimum) and Claude Code 2.1.284. A managed Mac can:

  • deny the microphone to an app by profile (MDM can deny the microphone, never grant it);
  • allow or deny Speech Recognition;
  • turn Dictation off (Restrictions). Not known yet whether that also stops SpeechTranscriber;
  • block Apple’s model download.

Duo tells these apart where macOS does (denied vs restricted) and shows each, on the board “The first press, and when it’s off”. A one-minute check by hand once a build has it (Q-180).
