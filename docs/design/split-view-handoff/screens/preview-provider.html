The interface between split view and a preview (agreed shape with duo-decks, proposed)
Duo Decks’ proposal (R1–R10, SourcePreview) with three changes: the name, a revision on every event, and render-from-buffer after DL-77 reconciles. Any viewer that can be the other side of a source implements it: the deck viewer first, then Markdown and HTML previews.
The editor (source side)Owns the caret and the lines
  • caret, selection, visible lines
  • reveals lines, marks problem lines
  • the formatting bar, review bar and dictation
  • DL-77’s reconcile with disk
textChanged(rev) →caretMoved(line) →visibleLines(range) →selection →← reveal(lines)← mark(problems)
Split viewOwns the policy
  • caret-follow (on), scroll-follow (off by default)
  • debounce: render 250 ms after typing pauses
  • loop suppression: every event carries its origin and revision
  • the split tab, divider, fold, making room, persistence
  • duo2 split …
render(text, rev) →reveal(anchor, reason) →← anchorMap(rev, [AnchorRange])← activate(anchor)← current(anchor)← problems(rev, [SourceProblem])
The preview (PreviewProvider)Owns the anchor map
  • canPreview(file, frontmatter): deck = type: deck
  • parses the source; the only one that can
  • draws from the buffer, never writes a file
  • its own bar: ‹ › n/N, problems, Select Shape, Export ⌄, export state
  • duo2 deck …
AnchorsAnchorRange = a source line range → an anchor. Deck: slide 3, slide 3/value. Markdown: a heading or block. HTML: an element id.
The revision ruleA provider drops a render older than its newest. Split view ignores an anchorMap or problems whose revision isn’t the editor’s current one. A reveal never echoes back as a caretMoved.
On a change on diskThe editor reconciles first (DL-77: merge, or the conflict bar), then split view sends one normal render. Both sides update together (R1).
What split view provides, and what it doesn’t
  • Provides: the split tab, making room (board 8), the fold at 2 × 340 with the names as a toggle, the active side and command routing (board 9), the sync policy, persistence (R10), duo2 split.
  • Slice 1 has same file, two views (source + its preview, one buffer). That’s the deck case.
  • Doesn’t provide: parsing, the anchor map, rendering, the problems list, the deck bar, export or its state, duo2 deck. Those are the provider’s.
  • Not in slice 1: two editable views of one file (ENH-301), or two editors side by side (slice 2).
