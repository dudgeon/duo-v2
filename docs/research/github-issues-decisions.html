What we found

Clone, pull and push never move issues.Issues, comments, labels, milestones and GitHub Projects live in GitHub's database. A repo exposes only branches, tags and each pull request's commits (checked on cli/cli: 266 branches, 205 tags, 5,398 PR refs, nothing else). They're read and written through GitHub's API: gh, REST, GraphQL or GitHub's MCP server.
What a repo does carry is the scaffolding.Issue templates and forms (which can add labels and a Project), the template chooser, PR templates and workflows, all in .github/. Labels can't be declared in a file.
Claude can already do all of it.In any repo session Claude runs gh issue create / edit / close / comment and gh project item-edit with your own sign-in. So Duo shouldn't become a second GitHub. It should show, link, make the common moves one click, and tell Claude what it needs (the DL-149 split again).
Projects need an extra permission you don't have yet.Your gh has repo, read:org, gist and workflow. Reading any Project, even a public one, needs read:project; dragging needs project. Asking for Project fields without it fails the whole issue query. Fine-grained tokens can't see user-owned Projects at all.
Signed out or offline, nothing comes through.Signed out, gh refuses even a public repo's issues. Offline it fails in 0.04 s. So anything Duo shows offline comes from its own cache, and a link must still work with no gh (the work Mac).
What others do: link by ID, derive status from events.Linear and Jira link through the issue ID in branches and PRs ("Closes #n" closes the issue on merge). VS Code has Start Working on Issue. Obsidian plugins pull issues into notes one way and overwrite them except a protected block. git-bug keeps issues in git, but teams on GitHub won't move. Nobody makes a local file the truth for a GitHub issue.
The recommendation in one paragraph

A task note can track one issue (issue: "https://github.com/…/issues/123"). The card and note show its live state. The task's status stays yours and the issue's state stays GitHub's, and Duo only offers to bridge them. The board gains an Issues lane of unlinked issues assigned to you: drag one into a lane and it becomes a linked task. Duo writes to GitHub only for Close/Reopen and New Issue from Task, plus "Closes #n" in the PR it opens. Triage stays with Claude. GitHub Projects come later, as a board source that reuses the same board.
