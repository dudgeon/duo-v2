Review in Markdown: tracked changes, comments and @claude

We want reviewing a Markdown document in Duo to feel like reviewing in Word or Google Docs, with Claude as one of the reviewers. Suggested edits you can accept or reject, comments with names on them, and a way to ask Claude something right where the question is. All of it kept in the Markdown file itself.

[P] Drawn Duo screens are proposals, not approved design Research: docs/research/markdown-review.md 27 Oct 2026
What people should be able to do
  • See what changed and who changed it. Suggested insertions and deletions show in each person's colour, with their name and when.
  • Accept or reject each suggestion, one at a time or all at once, and get exactly the old or the new text back.
  • Comment on a passage, reply in a thread, and resolve or dismiss the thread when it's dealt with.
  • Ask Claude from inside the document. Write @claude in a comment; it reaches a Claude session as a message, and Claude answers in the thread, or proposes the change as a suggestion.
  • Have Claude's edits wait for you when you want them to, instead of landing straight in the text.
  • Keep one plain file. No hidden companion file. The document still opens in Obsidian, on GitHub and in any text editor, and the review is readable there.
  • Bring Word reviews across. Converting a .docx keeps its comments and tracked changes instead of dropping them.
User stories

A PM reviews a doc Claude wrote

Geoff, product manager
  1. Claude drafts offline.md in a session.
  2. Geoff reads it in Duo, highlights a claim and comments "Is this true for crash reports?"
  3. He fixes a number himself, and leaves two more comments.
  4. Next morning he sees which comments are open and which Claude has answered.

Claude proposes changes for approval

Geoff and the session that wrote the doc
  1. Geoff turns on Suggest Edits for the document.
  2. He asks Claude to tighten the intro. Claude's edits arrive as green suggestions, signed by Claude, and the text underneath is unchanged.
  3. He accepts two, rejects one, and the doc is clean again.

A team-mate's comments

Sam reviews the same file in Obsidian, pulled through git
  1. Sam adds comments and a suggestion in Obsidian (with or without a review plugin).
  2. Geoff's Duo shows them in Sam's colour, with Sam's name.
  3. One of Sam's comments says @claude; Duo shows it as not sent with a Send button, so nothing starts on its own.

@claude, rewrite this

Geoff, mid-review
  1. Geoff comments "@claude can you tighten this paragraph?"
  2. The comment shows which session will get it before he posts it.
  3. Claude replies in the thread and proposes the rewrite as a suggestion.
  4. Geoff accepts it and resolves the thread.
How it would look in Duo [P]

These follow the review look Duo already has for Word documents (DL-162): each person's colour, comment cards under their paragraph, a hover label, resolved threads folded. Colours and controls are Duo's tokens. Everything here is a proposal for the decisions below.

Decisions

Twelve choices to lock

How to answer. Pick an option on each card; picks save as you go. Our recommendation is listed first on every card. Add a note if you like, then Send on the card, or Send my picks at the bottom. Send also passes your picks to Claude (for editors of this page). To leave any other feedback, use Comment on this or the page's comment mode.
Picks save for signed-in people who can contribute to this page.
